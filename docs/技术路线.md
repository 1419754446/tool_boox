# 工具箱 · 技术路线与工程说明

## 1. 结论

一条路线收口三个程序：**C++20 + Win32 + WebView2，前端 HTML/CSS/JS 内嵌进 exe，前后端走 JSON 命令总线**。

选它的依据：

| 路线 | 复用度 | 单文件体积 | 结论 |
| --- | --- | --- | --- |
| A. C++20 + Win32 + WebView2 | 最高：`tool_soft` 的 14 个文件工具本来就跑在这个栈上，视频引擎也是同一套 C++ 后端 | 约 5 MB | **采用** |
| B. Python + PySide6 | 要重写 14 个工具 | 100 MB+ | 放弃 |
| C. Python 后端 + WebView | 前后端两套依赖，打包更麻烦 | 60 MB+ | 放弃 |
| D. C# + WinForms/WPF | 只有常用文件夹能直接复用 | 20 MB+ | 放弃 |

本机实测不需要再装任何编译工具：MSYS2 的 `g++ 16.2.0` 在
`D:\SoftWare\msys64\ucrt64\bin`，WebView2 Runtime 已安装。

## 2. 底座与扩展方式

底座直接沿用已经跑稳的 `tool_soft` 外壳，而不是重写一遍：

- 原生：`src/app.cpp` 负责窗口、WebView2 宿主、14 个文件工具的任务编排；
- 前端：`web/index.html + styles.css + js/01..08-*.js`（按前缀拼成一份脚本），构建时内联成**一个** HTML，作为资源 101 编进 exe；
- 新工具（常用文件夹、视频整理）**不再走老的外壳消息**，走统一命令总线。

命令总线协议：

```json
// 前端 → 原生
{"id":"<uuid>","cmd":"folders.load","args":{...}}
// 原生 → 前端
{"type":"response","id":"<uuid>","ok":true,"data":{...}}
```

前端封装成 `toolCall(cmd, args)`，返回 Promise；原生侧
`tb::Bridge`（`src/bridge.h/.cpp`）是一张 `命令名 → 处理函数` 的表，
未注册的命令返回错误，处理函数抛异常也被兜住。

长任务（视频扫描/整理）不占用响应的生命周期：命令立即返回
`{"started":true}`，进度用 `tb::PostMessage()` 从**任意线程**推给前端，
外壳内部转投 UI 线程（`WM_APP+5`），消息类型统一加 `video.` 前缀。

## 4. 已合并的工具（16 个）

- 来自 `tool_soft`（14）：大文件扫描、空文件夹清理、重复文件查找、磁盘空间分析、
  批量重命名、文件哈希校验、临时文件清理、文件占用解锁、快速文件搜索、
  文件夹对比同步、剪贴板历史、文件整理、U盘安全弹出、截图工具。
- 来自 `_desktop_links`（1）：常用文件夹（清单 `路径 | 备注`，支持环境变量、缺失标注、
  写前备份 `folders.bak.txt`、条目上移下移）。悬浮小窗里额外提供搜索高亮、内联增删改、
  复选框多选/批量删除、打开清单文件、F2/Delete/Ctrl+F/Ctrl+A/数字键。
- 来自 `video-collector`（1）：视频整理（按扩展名/体积/排除目录扫描、内容指纹去重、
  同名跳过/自动改名、复制或移动、逐条状态与日志）。列表额外读取缩略图、时长与
  分辨率：`video.meta` 命令在独立 STA 线程里用 Shell 属性系统取
  `PKEY_Media_Duration / PKEY_Video_FrameWidth / FrameHeight`，再用
  `IShellItemImageFactory` 取图、GDI+ 转 JPEG data URL 回传，前端按可视行懒加载。
  预览用 `video.preview` + `src/media_handler.cpp`：`https://media.local/<文件名>`
  由原生按 Range 读取当前目录，不把整个视频读进内存；失败回退系统播放器。
  另有筛选、导出 CSV、**自包含 HTML 报告（前端生成后走 `exportFile`）**、
  删除到回收站（可勾选「同时删除目标文件夹中的副本」）、批量删除、移动确认、
  完成后打开目标、撤销本次整理；表头复选框支持半选，`F1` 打开全局快捷键说明。
  源/目标/格式/体积/重名策略等设置存 `localStorage` 的 `toolbox.videoSettings`，
  重开悬浮窗或主窗口自动恢复。
- `tool_folders.cpp` 另注册了通用 `file.open` / `file.reveal`，供搜索结果打开任意文件。

## 5. 加一个新工具（四步）

1. `src/tools/tool_xxx.cpp`：实现 `tb::RegisterXxxCommands()`，在函数里
   `Bridge::Get().Add("xxx.yyy", handler)`；需要长任务就调 `tb::PostMessage()` 推进度。
2. `src/tools/tool_xxx.h` 声明注册函数，在 `src/bridge.cpp` 的
   `RegisterAllCommands()` 里加一行调用。
3. `web/js/` 里对应块：
   - `TOOLS` 数组加一条 `{id, name, desc, category, icon, accent, status, tags}`；
   - `renderToolPage()` 加 `if (tool.id === 'xxx') return renderXxx(tool)`；
   - 照 `常用文件夹 / 视频整理` 的写法用 `toolCall('xxx.yyy', {...})` 调后端。
4. `build.ps1` 重新构建，产物仍是单个 exe。

图标：在 `ICON_PATHS` 里加一条 SVG path 即可，不需要外部图片。

## 6. 常驻、托盘与唤出

- 关闭主窗口不退出：`WM_CLOSE` 在非退出流程里只做 `ShowWindow(SW_HIDE)`，进程留在托盘。
- 托盘：`Shell_NotifyIconW`，单击开/收常用文件夹悬浮窗，双击打开主窗口，右键菜单含
  「打开主窗口 / 常用文件夹面板 / 悬浮工具（悬浮工具箱 + 四个常用工具）/ 开机自启 / 退出」。
- 全局热键 `Ctrl+Alt+Shift+F`：`RegisterHotKey` + `WM_HOTKEY`，与托盘单击同一个开关。
- 开机自启：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `Toolbox`，
  值为 `"<exe>" --startup`；托盘菜单勾选切换，也可用 `--autostart=on|off` 无窗口开关。
- 通用悬浮窗：`src/mini_window.cpp`，`WS_OVERLAPPED | WS_CAPTION | WS_THICKFRAME` 的
  普通小窗，每个窗口一个独立 `ICoreWebView2Controller`，加载同一个内嵌页面的
  `?mini=1&tool=<id>`。前端识别 mini 模式后隐藏侧栏/顶栏，只渲染工具页；迷你顶栏
  一行放下「悬浮工具箱 / 打开主窗口 / 置顶 / 收起 / 关闭」；拖到工作区四边 18px 内
  吸附；`WM_CLOSE` 只隐藏；`WM_NCLBUTTONDBLCLK` 收起/展开。状态写 `mini-state.ini`。
  收起（折叠）不是隐藏 WebView，而是把客户区压到 44 逻辑像素、由前端渲染一条
  「图标 + 名称 + 主窗口/置顶/展开/关闭」的折叠条；高度一律按客户区经
  `AdjustWindowRectEx` 换算外框（直接设外框会把标题栏吃掉，旧版设 36 的结果是
  客户区只剩 1px，看着像收不起来）。启动时前端主动拉一次 `mini state`，
  所以上次折叠着关掉的窗口会直接以折叠条恢复。
  默认尺寸按工具收紧（常用文件夹 318×432、视频 776×512、工具箱 452×528 等，
  逻辑像素），首次开窗按工作区夹取。
- 任意工具可悬浮：`pageHead()` 在非 mini 模式自动追加「悬浮」按钮，点击发
  `miniOpen`；原生 `ShowMiniWindow(toolId)` 按 id 复用或新建窗口。
- 悬浮工具箱：`launcher` 页面带搜索框，输入即按名称/标签过滤 16 张卡片；
  设置页「悬浮窗」面板提供同一套入口。
- 视觉层：`web/styles.css` 末尾的 v0.3 段落覆盖令牌与组件（浅色 Aurora 背景、
  统一 9/16px 圆角、卡片悬浮反馈、紧凑表格），不改动原有页面结构，深色主题仍可用。
- 高度自适应：前端在 `render()` / 数据刷新后测量 `.view` 的真实内容高度（临时
  `height:auto; flex:0 0 auto`），发 `{type:'mini',payload:{action:'fitHeight',height}}`；
  原生 `MiniWindow::FitHeight` 换算 DPI、夹到工作区后 `SetWindowPos`。用户拖动过高度
  （`WM_EXITSIZEMOVE` 里发现客户区变化）就把 `FitH=0` 写进 ini，不再自动改。
  `SaveState` 存客户区尺寸（此前误存外框，反复开关窗口会越来越大）。
- 任务栏按钮：`ITaskbarList::AddTab/DeleteTab` 增删主窗口按钮，不改窗口样式，
  所以标题栏外观不变；开关存 `app.ini` 的 `[window] Taskbar`，默认 1。
- 独立预览窗：`ShowPreviewWindow(path, name)` 另开一个 `ToolId=video-preview` 的悬浮窗，
  把路径/文件名 percent-encode 进 query，前端 `renderPreviewWindow` 调 `video.preview`
  拿 `https://media.local/...` 地址播放；每次打开都新建，避免复用成上一部画面。
- 扫描后内容分组：`JobOptions::dedupeScan` 打开时，`RunScanOnly` 末尾按体积分桶，只有
  同体积的文件才算 `FileFingerprint`（首/中/尾各 64KB，FNV-1a），同指纹的发
  `dedupe_group`（keep/ids/size），每 100 个文件发一次 `dedupe_progress`；全程只读、
  可取消，不改任何文件状态。前端把结果标在行上，并给一个「每组保留一份」取消重复勾选。

## 7. 数据目录

运行数据在 `%LOCALAPPDATA%\Toolbox\`：

- `folders.txt` / `folders.bak.txt`：常用文件夹清单与备份
- `mini-state.ini`：每个悬浮窗的 X/Y/W/H、置顶、收起状态、`FitH`（是否自动高度）
- `app.ini`：外壳设置（`[window] Taskbar=0|1`）
- `web\`：构建时释放的界面文件（按内容哈希命名，避免旧缓存）
- `bin\WebView2Loader-<hash>.dll`
- `WebView2\`：浏览器缓存与 localStorage
- `screenshots\`：截图工具的输出

放一个空的 `portable.ini` 到 exe 同目录，数据目录会改为 exe 旁的 `data\`。

## 8. 构建

```powershell
cd D:\Document\Code_test\all\toolbox
pwsh -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

脚本内部已经把 `D:\SoftWare\msys64\ucrt64\bin` 加到 `PATH`。
这一步不能省：`cc1plus.exe` / `ld.exe` 依赖同目录的 DLL，只写编译器绝对路径会
**静默失败**（退出码 1、零输出）。换机器时改脚本顶部的 `$gxx` / `$windres` 即可。

运行：

```powershell
.\dist\Toolbox.exe                          # 首页
.\dist\Toolbox.exe --page tool=folders      # 直达常用文件夹
.\dist\Toolbox.exe --page tool=video-collector
.\dist\Toolbox.exe --panel                  # 只弹常用文件夹浮层
.\dist\Toolbox.exe --startup                # 静默进托盘（开机自启用这个）
.\dist\Toolbox.exe --quit                   # 退出已运行实例
```

视频整理支持带参数启动（快捷方式 / 脚本用）：

```
--page "tool=video-collector&vroot=D:\Videos&vdst=D:\Keep&vauto=1"
```

## 9. 已知边界 / 待办

- 缩略图依赖系统缩略图缓存与解码器；首次读取可能慢一两秒，读不到时列显示「—」，
  不阻塞扫描和整理。
- 内置播放器依赖 WebView2/系统解码器：mp4/mov/webm 一般能直接播，部分 mkv/rmvb/ts
  可能解不了，预览框里有「系统播放器」回退。
- 撤销只保留最近一次整理；移动的移回原位，复制产生的目标副本移入回收站。
- 超长路径（>260 字符）依赖系统 `LongPathsEnabled`，失败时会在状态里点明原因。
- 单实例：重复启动会激活已有窗口；构建脚本会先 `--quit` 请旧进程退出，
  1.5 秒后仍在则 `Stop-Process -Force`（关闭按钮已改为收进托盘）。
- 旧版 GDI 文件夹浮层 `folders_panel.*` 仍参与编译但无调用方，保留仅作回退参考。
- 逐项差异与未做的细节见 `docs/功能对照.md`。
